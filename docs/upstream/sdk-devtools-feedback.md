## 요약 블록 (그대로 붙여넣기용, 수신처별)

전달 채널이 확정되면 아래 두 블록을 각 수신처에 붙여넣는다. 4번(permission
미정리)은 층위 재확인 전까지 어느 블록에도 포함하지 않는다.

> **[SDK] 에러 메시지·getLocation 세분화·지도 API 수요 — harness 도그푸딩 관측**

## 관측 항목

각 항목은 {관측(익명화) · 소관 추정 · 전달 시 요청할 것} 구조로 정리했다.
실기기에서만 재현되는 것과 mock 층(devtools) 문제를 구분해 서술했으며,
소관이 불확실한 경우 단정하지 않고 관측 사실만 남긴다.

### 1. SDK 에러 메시지 전반 개선 요청

- **관측**: 도그푸딩 세션에서 SDK 호출 실패 시 에러 메시지가 원인 파악에
  불충분하다는 지적이 반복 관측됐다. 특정 API 하나에 국한된 문제가 아니라
  전반적인 경향으로 언급됐다.
- **소관 추정**: SDK 런타임 (wf 소스 monorepo(사내) 소유 — harness가 직접
  수정할 수 없다).
- **전달 시 요청할 것**: 에러 메시지 전반에 원인을 식별할 수 있는 정보(에러
  코드·구체적 사유)를 보강하는 방향 검토를 요청한다.

### 2. `getLocation` 권한 다이얼로그 미노출 시 에러 세분화 부재

- **관측**: `getLocation()` 호출 시 권한 요청 다이얼로그가 뜨지 않는 상황이
  관측됐다. 이때 SDK가 반환하는 에러가 원인(권한 거부/설정 문제/기타)을
  구분해주지 않아, 에이전트도 사용자도 다음 행동을 정할 수 없어 진단
  루프가 끊겼다. **이 현상이 실기기에서만 재현되는지, devtools mock 층에서도
  재현되는지는 이번 세션 기록만으로는 특정되지 않는다** — 재현 조건(디바이스,
  OS, 권한 상태, mock 사용 여부)이 기록에 남아 있지 않다.
- **소관 추정**: SDK 런타임의 에러 세분화 문제로 추정하나 미확정 —
  실기기 전용 재현인지 mock 포함 재현인지 구분이 필요하다.
- **전달 시 요청할 것**: 권한 다이얼로그가 뜨지 않는 상황에 대한 에러
  코드/메시지 세분화, 그리고 재현 조건(디바이스·OS·권한 상태) 재현 절차
  명세를 요청한다.

### 3. devtools `shareLink` mock 값 혼동

- **관측**: 로컬 개발 환경(devtools mock)의 `shareLink` mock이 실제 토스 앱
  링크 형식의 URL을 반환한다. 처음 접하는 사용자가 그 URL을 열어보고
  동작하지 않는 것에 혼동을 겪는 사례가 관측됐다.
- **소관 추정**: devtools mock (AIT-6577, wf 소스 monorepo(사내) 소유 —
  harness `packages/devtools` 사본은 제거돼 harness가 직접 수정할 수 없다).
- **전달 시 요청할 것**: mock 반환값을 실제 링크 형식 대신 mock임이 명확한
  placeholder로 바꾸거나, 최소한 mock 값임을 알리는 안내를 동봉하는 방향
  검토를 요청한다.

### 4. permission(권한) 관련 미정리 항목 — 재확인 필요, 전달 보류

- **관측**: 도그푸딩 세션에서 permission 관련 항목이 미정리 상태로
  언급됐으나, **OS 런타임 권한 / 콘솔 약관 / OAuth 스코프 중 어느 층위를
  가리키는지 세션 기록만으로는 특정되지 않는다.**
- **소관 추정**: 미확정 — 층위가 특정되기 전까지는 SDK 런타임(2번과 같은
  축일 개연성 있음) · 콘솔 · 인증 중 어느 것도 배제할 수 없다. 재확인 시
  `packages/agent-plugin/shared/skills/plan/SKILL.md`의 도메인별 권한·약관
  표(런타임 권한 열 vs 콘솔 약관 열)를 선택지로 제시하면 특정이 빠를 것으로
  판단된다.
- **전달 시 요청할 것**: (해당 없음 — 층위가 특정되기 전까지 전달 대상에서
  제외한다. 특정되면 2번과 병합하거나 별도 항목으로 재분류한다.)

### 5. 지도(Map) API 수요

- **관측**: 도그푸딩 중 지도 API에 대한 수요가 다수 관측됐다(기능 요청
  성격 — 결함 아님).
- **소관 추정**: SDK/web-framework 기능 범위 (wf 소스 monorepo(사내) 소유).
- **전달 시 요청할 것**: 지도 API 지원 여부·로드맵 반영 가능성 확인을
  요청한다.

## 공통 사항

- 위 항목은 모두 도그푸딩 세션 기록을 익명화해 정리한 관측이며, 참여자
  식별 정보·구체 워크스페이스 등은 포함하지 않는다.
- 4번을 제외한 1·2·3·5는 관측 사실과 소관 추정을 담은 것이지, harness
  쪽에서 재현 절차를 완주 검증한 결함 리포트는 아니다 — 전달 시 수신처가
  추가 재현을 요청할 수 있음을 감안한다.
- 2번이 해소되면 `debug` skill의 진단 단서에 반영한다(원 이슈 #108의 할 일
  항목).
