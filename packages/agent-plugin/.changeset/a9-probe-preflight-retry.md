A9(skill 본문 주입 실측) probe가 환경 문제를 skill 개수만큼 fan-out하던 문제를 고친다. 실측(claude 2.1.272)에서 미로그인 프로필은 skill 전체가 동일한 `claude CLI 종료 코드 1`로, 401 API 키는 skill 전체가 동일한 `180000ms 초과로 강제 종료`로만 찍혔다 — 진짜 원인 문장은 항상 stdout(stream-json) 안에 있는데 실패 시 그걸 버리고 stderr tail(거의 항상 0바이트)만 보여줬기 때문이다. 이제 skill 세션을 띄우기 전에 같은 argv로 "pong" 사전 점검을 1회 돌려 로그인·플러그인 로드·skill 등록 문제를 전역 1건으로 잡고, 401/403 API 재시도는 CLI가 무한 반복하므로 관측 즉시 죽이며, `cli-error`/`no-route`는 일시 장애일 수 있어 1회 재시도(`no-body`/`mismatch`는 결정적 관측이라 재시도 안 함)하고, match가 아닌 시도의 stdout/stderr/진단을 디스크에 transcript로 남긴다. 타임아웃 진단에는 벽시계가 타임아웃을 5초 넘게 초과한 만큼을 적어 덮개 닫힘 절전·일시정지 흔적이 드러나게 했고, stdout 청크 경계에서 한글이 깨져 거짓 mismatch가 나던 잠복 결함도 `setEncoding('utf8')`로 고쳤다.

이어서 같은 probe의 2차 실측(2026-09-16, claude 2.1.273)에서 드러난 네 가지를 더 고친다. skill 본문 주입 이벤트를 stdout에서 보는 즉시 세션을 끝내고, 세션이 어떻게 끝났든 주입 이벤트가 있으면 match/mismatch로 판정한다 — 본문이 이미 들어온 뒤 모델이 그 지시를 따라 도구를 계속 돌다 180초 타임아웃으로 죽은 세션이 `cli-error`로 찍히고 재시도로 180초를 한 번 더 태우던 것을 정정한다. SIGKILL 뒤 종료를 기다리는 상한(5초)을 두고 타이머 지각분과 kill 후 종료 지연을 따로 재, 파이프를 물고 있던 자식 프로세스 때문에 늦은 종료가 "절전"으로 오진되던 것을 원인별 문구로 나눈다. 사전 점검은 전체를 막는 관문이라 실패가 일시 장애형(API 재시도 없는 타임아웃, result 이벤트도 없는 종료)일 때만 1회 재시도하고, 재시도로 통과하면 1차 실패를 경고와 transcript로 남긴다. 모델 대체는 `init.model`이 요청 문자열을 그대로 돌려주므로 `model_fallback` 이벤트와 assistant 이벤트의 실제 모델로 판정한다 — 경고가 "요청 모델 X를 인식하지 못해 X로 대체됨"이라는 자기참조 문장이 되던 것을 정정한다. 관측 즉시 끝낸 세션에 kill 대기 상한 초과나 타이머 지각이 있으면 `A9/ok` 문구 끝에 세션 메모로 남기고(통과 세션은 transcript를 저장하지 않으므로 이 메모가 유일한 흔적이다), 사전 점검이 재시도 뒤 플러그인·skill 등록 검사에서 떨어져도 1차 실패 경고를 버리지 않는다. Skill 도구가 한 번도 안 불린 채 `result-error`로 끝난 세션은 `no-route`가 아니라 `cli-error`로 분류해 발화·description 문제를 가리키던 안내를 정정하고, `A9/info` 한 줄에 API 키 출처와 플러그인 출처를 실어 어느 자격증명·어느 설치 형상에서 쟀는지 남긴다.
