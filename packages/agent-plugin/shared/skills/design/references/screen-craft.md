# 화면 제작 순서 (screen-craft)

quality bar(`references/quality-bar.md`, G0~G8)가 이미 만들어진 화면을 판정하는
기준이라면, 이 문서는 **그 기준을 처음부터 만족하는 화면이 나오도록** 제작
순서를 정한 것이다. 판정 항목을 새로 만들지 않는다 — 각 순서 항목은
quality-bar.md의 해당 항목을 가리키기만 하고, 항목 정본은 항상
quality-bar.md다.

## 이 문서의 지위

- quality-bar.md = 사후 채점 기준. screen-craft.md = 그 채점을 통과하도록
  뒤집은 사전 체크리스트.
- 여기서 "통과"라고 부르는 것은 quality-bar.md의 등급 체계(통과/조정
  필요/해당 없음)를 그대로 쓴다는 뜻이 아니다 — 이 문서 단계에서는 아직
  화면이 없으므로 판정 자체가 성립하지 않는다. 실제 판정은 화면이 만들어진
  뒤 2-C 단계에서 quality-bar.md로 한다.
- 이 문서만 읽고 화면을 만들어도 판정을 건너뛸 수 있는 것은 아니다 — 순서를
  따랐어도 2-C 판정은 그대로 거친다.

## 순서

아래 순서대로 정하면, 뒤 단계에서 앞 단계를 다시 뒤집는 재작업이 줄어든다.
괄호 안은 이 결정이 어긋났을 때 quality-bar.md에서 걸리는 항목이다.

1. **화면 목록과 목적을 먼저 고정한다.** 화면마다 한 줄로 "이 화면은 무엇을
   하는 화면인가"를 적는다. quality bar의 판정 단위가 화면이므로, 화면
   목록이 흔들리면 판정 단위 자체가 흔들린다.
2. **화면마다 주요 액션을 하나만 정한다.** 동급 CTA를 나열하지 않는다 —
   버튼이 여러 개 필요하면 그중 하나를 주 액션으로, 나머지는 보조로
   내려놓는다 (G4-1).
3. **정보 계층을 먼저 정하고(예: 제목/본문/보조 3단), 그다음 크기·굵기를
   배분한다.** 계층을 정하지 않고 크기부터 정하면 위계가 크기 순서로만
   남는다 (G3-5·G3-6·G4-6). 단수는 예시일 뿐이다 — 화면에 맞는 계층
   수를 정하는 것은 자유이고, quality bar가 요구하는 것은 "계층을 먼저
   정한다"는 순서이지 특정 단수가 아니다.
4. **행복 경로를 그리기 전에 로딩·빈·실패·권한 거부 4상태를 먼저 적는다.**
   나중에 붙이면 누락되기 쉽고, 화면 구조가 행복 경로 하나만 전제한 형태로
   굳는다 (G5).
5. **색·타이포·spacing을 이름 있는 토큰으로 먼저 정의하고, 화면은 토큰만
   쓴다.** 매직 넘버(화면마다 새로 정하는 hex·px 값)를 화면 단계에서 만들지
   않는다 (G3-1~G3-3).
6. **컨테이너 제약을 레이아웃 골격에 넣는다.**
   - 상단 safe-area inset은 `env()`와 spacing 토큰의 조합으로 잡는다(고정
     padding 하나로 대신하지 않는다).
   - 좌측 엣지에 가로 드래그 UI(캐러셀·슬라이더)를 두지 않는다.
   - 헤더를 이중으로 쌓지 않는다(커스텀 헤더 + 컨테이너 헤더).
   (G1)
7. **조작 하한을 컴포넌트 기본값으로 박는다.** 터치 타깃 하한과 본문 대비를
   버튼·입력 등 컴포넌트 정의 자체에서 만족시켜, 화면을 만들 때마다 다시
   재지 않게 한다 (G4-3·G4-4).
8. **렌더가 깨지는 형태를 만들지 않는다.**
   - 고정 높이 컨테이너에 가변 길이 텍스트를 담지 않는다.
   - 이미지에 종횡비를 강제로 늘리거나 눌러 맞추지 않는다.
   - 방향·행동 아이콘(chevron·화살표 등)은 인라인 SVG로 넣는다(텍스트
     글리프로 때우지 않는다).
   - 한국어 본문 블록에 `word-break: keep-all`을 기본으로 둔다.
   (G7)
9. **사용자를 가두는 패턴을 설계 단계에서 배제한다.** 닫기 없는 전면 요소,
   진입 직후 차단, CTA를 가리는 고정 배너를 처음부터 화면 설계에 넣지 않는다
   (G8).

이 순서를 통과했다고 자동으로 완료가 되는 것은 아니다 — 화면이 만들어진
뒤에는 반드시 2-C 단계에서 quality-bar.md로 다시 판정한다.

## 산출물 형식

이 순서를 따라가며 화면마다 아래 표 한 줄을 채운다. 실제 판정(통과/조정
필요/해당 없음)은 quality bar로 넘기고, 이 표는 그 판정을 받기 전 설계
상태를 정리하는 용도다.

| 화면 | 목적 | 주요 액션 | 정의된 상태 | 쓰는 토큰 | 걸리는 컨테이너 제약 |
|---|---|---|---|---|---|
| 홈 | 최근 항목을 한눈에 보여준다 | 새 항목 만들기 | 로딩·빈·실패 | `color/surface`, `color/text-primary`, `space/md` | safe-area inset(상단) |

값(토큰 이름·수치)은 예시일 뿐이다 — 실제 값은 프로젝트가 정한 것을 쓴다.

## 하지 않는 것

- ❌ 값을 지어내지 않는다 — 색·spacing·타이포 수치는 프로젝트 토큰이
  정본이고, 이 문서는 새 수치를 도입하지 않는다.
- ❌ 특정 디자인 시스템의 토큰 값을 추측해 쓰지 않는다.
- ❌ 화면 코드를 대신 전부 작성하지 않는다 — 이 문서는 만들기 전 순서를
  정리하는 체크리스트이지, 코드 생성기가 아니다.
- ❌ quality-bar.md의 판정 항목을 이 문서에서 다시 정의하지 않는다 — 항목
  정본은 항상 quality-bar.md다.
